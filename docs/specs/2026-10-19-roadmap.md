# braintools functionality roadmap (v0.3 → v1.0)

- **Status:** proposed, 2026-10-19
- **Verified against:** `origin/main` @ `2e0c016` (after #127)
- **Scope:** functionality and package layout. Each phase gets its own implementation spec in `docs/specs/` before any code is written (AGENTS.md rule 7).

## Context

braintools calls itself "Modeling tools for brain simulation", but its current shape fits that description only partly.

- **Generic ML dominates.** About 45% of the source is generic ML infrastructure: `optim`, `trainer`, and the loss half of `metric`.
- **Brain-specific analysis is thin and scattered.** Spike, LFP and functional-connectivity functions sit inside `metric`, next to ranking losses.
- **The ecosystem has gaps that no BrainX package fills:**
  - spike-train statistics (ISI/CV/Fano/PSTH/correlograms);
  - population analysis;
  - model-to-data fitting (only brainmass's neural-mass-specific `Fitter` exists);
  - neuro data I/O (NWB/HDF5);
  - adaptive ODE integration.
- **Accumulated debt:**
  - Distance kernels are re-implemented in `conn/_kernel.py` and `conn/_compartment.py`.
  - Spike data is handled in four inconsistent ways. For example, `metric.raster_plot(sp, ts)` and `visualize.raster_plot(ts, sp)` take their arguments in opposite orders, and `visualize/_utils.py` has its own spike helpers.
  - Some top-level modules belong in a subpackage (`_spike_encoder.py`, `_spike_operation.py`).
  - The README says conn supports "degree constraints" and "population networks"; it supports neither.
  - brainevent is imported but not declared as a dependency.
  - 26 test files have no matching source module (AGENTS.md rule 9).
  - CI runs Python 3.13 only, although 3.11–3.14 is advertised.

**Goal:** make braintools *the toolbox around brain models*, with tools to build, simulate, train, analyze and fit them.

### Decisions

- Cover all four directions: consolidation, analysis depth, model fitting, and building blocks.
- API changes follow **deprecate-then-remove**: old names keep working, with a warning, for at least one minor release, and are removed at 1.0.
- Add a new `braintools.analysis` package. Spike, spectral and correlation functions move there out of `metric`, which keeps only losses and similarity measures.
- Keep and extend `optim`. **Freeze** `trainer`: maintenance only, no new features.
- Dynamical-systems analysis in the style of brainpy 2.x `analysis/` is out of scope (see §1).
- Add a new model-agnostic `braintools.fit`. Simulation-based inference is out of scope for now.

## 1. Scope charter

| Owner | Owns |
|---|---|
| **brainstate** | Runtime: State, Module, `nn.Param`/Transform, transforms (jit, vmap, for_loop, jacobian), nn layers, stateful evaluation metrics |
| **brainevent** | Sparse/event kernels and connectivity storage (CSR, FixedNum, JIT connectivity) |
| **brainpy_state / brainmass / braincell** | Model equations and model-specific helpers |
| **braintools** | Model-agnostic tools to build model inputs, drive models numerically, train or fit them, and analyze, store and plot their data |

**Placement rule:**
- model equations → a model package;
- runtime or transform primitives → brainstate;
- sparse kernels or storage formats → brainevent;
- everything else → braintools.

**Out of scope:**
- Dynamical-systems analysis as in brainpy 2.x `analysis/`: phase plane, bifurcation, fixed/slow points, stability, Lyapunov exponents.
- Simulation-based inference.

## 3. Cross-cutting foundations

1. **One deprecation mechanism.** Move `input/_deprecation.py` up to `braintools/_deprecation.py`.
   - Aliases warn **when called**, not when accessed. `brainpy/measure.py` and `brainpy/visualization.py` bind `braintools.metric.*` and `braintools.visualize.*` names at import time, so access-time warnings would fire on every `import brainpy`.
   - A registry test checks three things: every alias warns, every alias's target exists, and CI fails once the alias's `removed_in` version is reached.
2. **`spike.SpikeTrains`.** A single pytree that holds spikes in two forms:
   - **Dense:** `(T, N)` plus `dt` and `t0`. This is what simulations produce.
   - **Padded events:** `times (N, K)` plus `counts (N,)`. This form is used for distances, ISI and I/O.

   Times are brainunit Quantities and the capacity `K` is static. Overflow is reported, never silently truncated.

   This one type unifies the spike conventions used today, including the helpers in `visualize/_utils.py` (`flatten_spikes`, `inter_spike_intervals`). It also lets us remove the host-side Python loops in `metric._firings`: `victor_purpura_distance`, `spike_train_synchrony`, `burst_synchrony_index` and `spike_time_tiling_coefficient`.

   Spectral, population and graph analysis take plain arrays and do not depend on `SpikeTrains`.

### 0.6 — Data and fitting (depends on A1–A3, C1, C3)

| # | Item | Size |
|---|---|---|
| F1 | `quad` solvers (details below) | L |
| F2 | `optim`: vmapped multi-start minimizer with convergence masks; the engine behind `fit`'s multi-start | M |
| F3 | `fit` workflow (details below) | L |
| F4 | `fit.losses` (details below) | M |
| F5 | `file` data formats (details below) | L |
| F6 | Cross-repo: re-base the brainmass `Fitter` (`brainmass/fitter.py`) on `braintools.fit` | M |

F1, `quad`:
- `odeint`: a `scan` driver over any existing stepper.
- Adaptive `solve_ivp`: a PI step-size controller using the rk45/dopri5 error estimate, run as a checkpointed bounded loop so reverse-mode gradients work.
- `get_method` / `register_method` registry.
- The existing `ode_*_step` names stay frozen, because brainmass looks them up by string.

F3, `fit`:
- A composable, weighted `Objective`.
- A `Fitter` that searches over `brainstate.nn.Param` or an explicit search space. Bounds reuse brainstate's bijectors (`SigmoidT`, `ClipT`, …).
- Gradient, scipy and nevergrad backends, with multi-start.
- `fit.sweep`: chunked vmap/map, replacing `brainpy.running`.

F4, `fit.losses`:
- Summary-statistic losses: firing rate, CV, PSD log-distance, functional connectivity.
- A differentiable van Rossum loss.
- KS, Wasserstein and FCD distances, moved here from `brainmass/objectives.py`.
- Hessian-based confidence intervals.

F5, `file`:
- NWB, mapping units ↔ `SpikeTrains` and TimeSeries (extra `[nwb]`).
- A NEO adapter (extra `[neo]`).
- HDF5 with unit metadata (extra `[hdf5]`).

**Exit criteria:**
- The brainmass fitter tests pass on `braintools.fit`.
- Known parameters are recovered on the Hopf and Wilson–Cowan models.
- NWB and HDF5 round-trip tests pass.

## 6. Design principles for new code

1. **JAX-native by default.** `analysis`, `spike`, `fit` and `quad` must work under jit and vmap with static shapes.
   - Host numpy is allowed only in `conn` (build time), `file`, `visualize`, and functions explicitly documented as host-only.
   - Every docstring states whether the function is jittable, vmappable and differentiable.
2. **Units.**
   - Accept and return brainunit Quantities.
   - `dt` comes from the argument, otherwise from `brainstate.environ.get_dt()`.
   - Never strip units silently.
3. **Functional core.**
   - Prefer pure functions. Use classes only for containers or composition (`SpikeTrains`, `Objective`, `Fitter`).
   - Time is axis 0, and trials are handled with vmap.
4. **No Python loops for rollouts or pairwise work** (AGENTS.md rule 10). Use `for_loop`, `scan`, `vmap` or chunked `map`, and `checkpointed_*` for backpropagation through time (BPTT).
5. **Heavy dependencies are optional extras.** Import them lazily, with an install hint in the error message.
6. **Reuse the ecosystem.**
   - Use brainstate `Param`/Transform for bounds, brainevent formats for connectivity, and brainstate's autodiff transforms (e.g. hessian).
   - Re-implement an algorithm natively only when it must run inside jit or grad, or at simulation scale. Otherwise provide `to_neo`-style interop rather than re-implementing Elephant or MNE.
7. **Explicit randomness.** Pass a key or seed; never use the global RNG.
8. **Repo conventions.** NumPy docstrings with doctests, co-located `foo_test.py`, coverage above 90%, reference-value tests, and a spec in `docs/specs` before each phase.

## 7. Ecosystem coordination and open questions

- **Two init hierarchies.** `brainstate.nn.init` duplicates `braintools.init`, yet `brainstate/_state.py` (`State.init`) imports `braintools.init.param`, so the dependency runs in the wrong direction. Which one is canonical needs a joint decision and a brainstate release. Proposal: make `braintools.init` canonical and keep a minimal internal default set in brainstate.
- **Two quad registries.** braincell has its own registry (`braincell/quad/_registry.py`). Proposal: braincell registers its implicit and staggered solvers through `quad.register_method` (F1).
- **Release lockstep.** brainpy 2.8.x (`measure.py`) and brainmass (`objectives.py`, `fitter.py`) need releases that switch to `analysis` / `fit` and pin `braintools>=0.4` / `>=0.6`.
- **Connectivity at scale.** Host-numpy conn does not scale to 1e6 neurons. Open question: give conn a device backend, or point users to brainevent's JIT connectivity? To be decided in the 0.7 spec.
- **`SpikeTrains` capacity.** Padded storage costs N×K. The default `K` and the overflow policy are to be decided in the 0.4 spec.
