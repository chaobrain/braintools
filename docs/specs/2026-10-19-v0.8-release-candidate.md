# v0.8: release candidate (spec and plan)

- **Roadmap:** `docs/specs/2026-10-19-roadmap.md`, phase "0.9 — Release candidate". The dynamical-systems phase was dropped, so this phase becomes 0.8.
- **Depends on:** phases 0.4–0.7.
- **Branch:** `phase/0.8-release-candidate`, stacked on `phase/0.7-building-blocks`. **PR:** one PR, based on the 0.7 branch.

## Goal

Make 0.8 the last release before 1.0. Every public name is documented, typed and has runnable examples. Deprecations become visible to end users, users get a migration guide, and the packages that have no tutorial get one.

The phase adds no new features. Behaviour changes only where a fix needs it, and each such change follows the repository's bug rule (a reproducing test first).

## Work packages

### R1: deprecations become visible, with a migration guide (WP-D)

- **Category.** `BraintoolsDeprecationWarning` subclasses `FutureWarning` instead of `DeprecationWarning`. `FutureWarning` is shown by default, which is Python's convention for deprecations aimed at end users of a library.
  - The class name stays, so `pytest.warns(BraintoolsDeprecationWarning)` and filters on that class keep working.
  - Code that filters on `DeprecationWarning` no longer catches it, which is the point of escalating. The changelog says so.
- **Single path.** The three modules that emit a plain `DeprecationWarning` move to registered records (`register_deprecation` plus `warn_deprecated`, removed in 1.0.0). Their messages keep the old text where tests or downstream code match on it.
- **Test filter.** The `pyproject.toml` `filterwarnings` entry matches the new category. Every test that expects these warnings is updated to the new category.
- **Migration guide.** A new page, `docs/migration.md` (in the toctree), contains a table of every registered deprecation (old name, replacement, kind, since, removed in) and short notes for the larger moves (`metric` → `analysis`, encoders → `spike`, `trainer` freeze). A test checks that every registered `old_name` appears in the guide, so new deprecations cannot be missed.

### R2: mypy over the whole package (WP-M1 … WP-M4)

- **Goal:** `mypy` with the repository options, run over `braintools/` with tests excluded, reports no errors.
- **CI:** the `files` list becomes `["braintools"]` with `exclude = '_test\.py$'`, and `TYPED_PUBLIC_MODULES` in `braintools/__init___test.py` is replaced by a check that the whole package is configured.
- **Rules:**
  - Fix with annotations, `Optional` narrowing, `cast` and small local refactors. Don't change behaviour.
  - A real bug found this way gets a failing test first, then the fix, and is reported.
  - `# type: ignore[code]` is allowed only with a specific error code and a short reason. Typical cases are wrong third-party stubs, or dynamic attributes on `brainstate` objects.
  - Public signatures can gain annotations but not lose parameters.

### R3: every public docstring example runs (same agents as R2, by package)

- **Goal:** all `>>>` examples in public docstrings pass under the doctest runner above. That covers every name in `__all__` plus its methods and properties, with `NORMALIZE_WHITESPACE | ELLIPSIS`.
- **Rules:**
  - Fix the example, not the code, unless the example reveals a real bug (then the bug rule applies).
  - Examples must be self-contained (imports, seeds) and show real output.
  - `# doctest: +SKIP` is allowed only for examples that need an external service or account (W&B, MLflow, Neptune, TensorBoard servers) or real accelerator hardware, and the skip is commented.
  - Output that varies between platforms uses `...` or rounding.
- **CI:** a new `scripts/run_doctests.py` runs the doctests of one package per process and fails on any failure. A `doctest` job in `.github/workflows/` runs it on Python 3.13. The NWB/NEO examples run in that job because it installs the `testing` extra.

### R4: API documentation completeness (orchestrator)

- Add the seven missing names to their `docs/apis/*.rst` pages.
- Add a test (in `braintools/__init___test.py`) that every name in a public `__all__` appears in an autosummary block of `docs/apis/`, so new names cannot be left undocumented.

### R5: tutorials (WP-T1, WP-T2)

- **WP-T1:**
  - `docs/spike/01_spike_trains.ipynb`: `SpikeTrains` (dense and event forms, conversions, capacity and overflow, units), the encoders, the bitwise operations, and plotting through `visualize`.
  - `docs/quad/trajectories_and_adaptive.ipynb`: `odeint` over steppers, `solve_ivp` against SciPy, `t_eval`, gradients through `checkpoint=True`, and the method registry.
- **WP-T2:**
  - `docs/trainer/01_training_loop.ipynb`: a small classification or regression model trained with `Trainer`, callbacks, checkpointing and logging to CSV. It states that `trainer` is in maintenance mode.
  - `docs/optim/06_readout_learning.ipynb`: FORCE learning of a target signal on a chaotic rate network (rollout in `for_loop`), RLS against ridge regression, lasso sparsity, and `multistart_minimize` on a multimodal function.
- **Requirements:** every notebook runs top to bottom (executed and stored with figures), finishes in under about 2 minutes on CPU, has an `index.md` entry and toctree, and drives models through `brainstate.transform` loops, never bare Python loops (AGENTS.md rule 10). Problems found in library code are reported to the orchestrator, not fixed in another agent's files.

### R6: release checks (orchestrator)

- **Packaging smoke.** Build the sdist and wheel. Install the wheel into a fresh virtualenv without extras, import every public subpackage, and call each optional-extra entry point to check its install hint (`nwb`, `neo`, `hdf5`, `viz`).
- **Changelog 0.8.0, README and docs index:**
  - the warning category change, the migration guide, typed package, doctests in CI, and the new tutorials;
  - a note on the 1.0 removal schedule.
- **Version.** `braintools/_version.py` stays at its current value. Choosing release version numbers is left to the maintainers, and the PR body says so.

**Conflict rule:** if WP-D needs to change a test file owned by an M agent (to update a warning category), it changes only the category assertion and tells the orchestrator. M agents leave deprecation categories alone.

**Memory rule (WSL):** each agent runs at most one test or notebook process at a time, with `XLA_PYTHON_CLIENT_PREALLOCATE=false JAX_PLATFORMS=cpu MPLBACKEND=Agg timeout ...`, and only its own packages' tests.

## Verification (exit criteria)

1. The full suite, one process per subpackage, has no failures. Coverage of the touched modules does not drop.
2. `mypy` (repository config, now the whole package) is clean.
3. `scripts/run_doctests.py` passes for every public package. NWB/NEO examples are checked in the reference environment.
4. The docs build has no new warnings, and the gate pattern grows to cover the new tutorial sections and `migration`.
5. The API-coverage and migration-guide tests pass.
6. Every new notebook is executed with stored figures.
7. Packaging smoke passes in a fresh virtualenv.
8. Downstream smoke matches the baseline: brainmass 114 passed plus 25 pre-existing fixture errors, brainpy_state 109, brainpy 136, brainstate 84, call sites OK. The category change must not turn any downstream test into a failure; if one does, that goes in the PR.

## Edge cases to test

- **Warning category:**
  - A deprecated alias warns with `FutureWarning` under default filters (in a subprocess with `-W default` removed), and is silenced by `filterwarnings('ignore', category=BraintoolsDeprecationWarning)`.
  - A filter on `DeprecationWarning` no longer catches it.
  - Pickling deprecated aliases still works.
- **Migration guide:** a missing entry fails the test.
- **The three converted modules:** each warns once per call, with the registered message, and stays silent when the deprecated path isn't used.
- **API coverage test:** names re-exported from subpackages, private names, and module objects in `__all__` are handled correctly.
