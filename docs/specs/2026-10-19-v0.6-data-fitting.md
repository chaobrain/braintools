# v0.6 — Data and fitting: spec and plan

- **Roadmap:** `docs/specs/2026-10-19-roadmap.md`, phase 0.6 (items F1–F6)
- **Depends on:** phase 0.4 (`SpikeTrains`, `_deprecation`) and phase 0.5 (`analysis`, used by the summary-statistic losses)
- **Branch:** `phase/0.6-fitting`, stacked on `phase/0.5-analysis`
- **PR:** one PR, based on the 0.5 branch

## Goal

braintools can fit any JAX/brainstate model to data. It gives you the pieces for that:

- a trajectory driver and an adaptive ODE solver (`quad`);
- a vmapped multi-start minimiser (`optim`);
- a model-agnostic `braintools.fit` package with composable objectives and summary-statistic losses;
- standard neuro data formats (NWB, NEO, HDF5) as optional extras.

## Global rules

These are the same as 0.5, rules 1–9: static shapes, jit/vmap tests, units, explicit keys, no Python loops over steps/starts/candidates, NumPy docstrings with doctested examples, co-located tests, coverage of at least 90%, and reference values. In addition:

1. **Optional heavy dependencies are imported lazily** inside the function. A missing package raises `ImportError` with the install hint `pip install braintools[nwb]`. Tests use `pytest.importorskip`.
2. **Frozen names.**
   - The `quad.ode_*_step`, `sde_*_step`, `imex_*_step` and `dde_*_step` functions keep their names and signatures, because brainmass looks them up by string.
   - The `optim` classes are unchanged.
3. **`fit` never mutates a model behind the user's back.**
   - Module-mode fitting writes the best parameters back only at the end of `Fitter.fit`, and the docstring says so.
   - Functional mode is pure.

## F1 — `quad`: trajectory driver, adaptive solver, method registry

New modules `quad/_odeint.py`, `quad/_solve_ivp.py` and `quad/_registry.py`, with co-located tests.

| Function | Behaviour |
|---|---|
| `odeint(f, y0, t0, t1, dt, *args, method='rk4', save_every=1, checkpoint=False, **kwargs)` | Fixed-step driver. Runs `n = round((t1-t0)/dt)` steps of `get_method(method)` inside `brainstate.environ.context(dt=dt)` as one `scan`. The step count is static, so `t0`, `t1` and `dt` must be concrete; under jit, pass `n_steps=` instead of `t1`. Returns `(ts, ys)`: `ts` has shape `(n//save_every + 1,)` and includes `t0`; `ys` is a pytree stacked on axis 0 starting with `y0`. `checkpoint=True` uses `checkpointed_scan` for backprop through time. Quantities are accepted for `y0`, `t0`, `t1` and `dt`. |
| `solve_ivp(f, t_span, y0, *args, method='dopri5', rtol=1e-6, atol=1e-9, dt0=None, max_steps=4096, t_eval=None, **kwargs)` | Adaptive solver. Uses the embedded error estimates already present (`ode_dopri5_step`, `ode_rk45_step`, `ode_rkf45_step`, `ode_rk23_step`/`bs32`) and a PI step-size controller (Hairer–Wanner II, with safety, min and max factors). The bounded loop has a static `max_steps` and a `done` mask, so it is reverse-mode differentiable. `t_eval` (static length) is filled by cubic Hermite interpolation between accepted steps. Returns `ODESolution(ts, ys, n_steps, n_rejected, success)`, a NamedTuple. If `t_eval` is None, `ts`/`ys` are the accepted steps padded to `max_steps+1` with the last value repeated, plus `n_steps`. The error norm is the RMS of `err / (atol + rtol*max(|y|, |y_new|))` on mantissas; `atol` may be a Quantity in `y`'s unit. If `dt0` is None, it is chosen by the Hairer–Wanner initial step heuristic. |
| `register_method(name, fn, kind='ode', *, overwrite=False)`, `get_method(name, kind='ode')`, `list_methods(kind=None)` | A registry pre-populated with every built-in stepper under its short name (`'euler'`, `'rk4'`, `'dopri5'`, …; for kind `'sde'`, `'milstein'`, …). An unknown name raises `KeyError` listing the close matches (`difflib`). Kinds: `ode`, `sde`, `imex`, `dde`. braincell can register its own solvers through this registry later. |

**Reference tests:**
- linear ODE and harmonic oscillator, with exact solutions;
- `scipy.integrate.solve_ivp(method='RK45'/'DOP853')` at matching tolerances on Lotka–Volterra and FitzHugh–Nagumo;
- the observed order of convergence of `odeint` for each RK method;
- reverse-mode `grad` through `solve_ivp`, checked against finite differences.

The quad module docstring's Python-loop examples are replaced with `odeint`, per AGENTS.md rule 10.

## F2 — `optim.multistart_minimize`

New module `optim/_multistart.py`.

`multistart_minimize(fun, x0, *, method='lbfgs', max_iter=500, tol=1e-6, bounds=None, learning_rate=1e-2)`

- **Function.** `fun(x) -> scalar` is pure and differentiable.
- **Starts.** `x0` is a pytree whose leaves have a leading axis of size S (the starts). The helper `multistart_init(key, bounds, n_starts)` draws uniform starts within bounds.
- **Execution.** One `jit`-compiled, `vmap`-ped `lax.while_loop`, with a per-start convergence mask: `|g|∞ < tol`, or a relative change in `f` below `tol`.
- **Methods.**
  - `'lbfgs'` uses `optax.lbfgs` with zoom linesearch.
  - `'adam'` and `'gd'` use optax.
- **Bounds.** `bounds` is a pytree of `(low, high)` pairs. Bounded leaves are optimised in an unconstrained space through brainstate's `SigmoidT(low, high)` bijector, and the result is mapped back.
- **Result.** `MultiStartResult(x, fun, converged, n_iter, best_x, best_fun, best_index)`, a NamedTuple.

**Tests:**
- Rosenbrock from many starts;
- a multimodal 1-D function, where all minima are found and the best is selected;
- bounded problems;
- vmap/jit behaviour.

This minimiser is also what the fixed and slow points of a later dynamics phase would use, if that phase is ever reinstated.

## F3 — `braintools.fit`: objectives, fitter, sweep, confidence intervals

New package `braintools/fit/` with `_objective.py`, `_fitter.py`, `_sweep.py` and `_uncertainty.py`, each with co-located tests.

**`Objective` and `Term` (`_objective.py`).**
- `Term(fn, weight=1.0, key=None, name=None)`:
  - `fn(prediction, target) -> scalar`;
  - `key` selects `prediction[key]`/`target[key]` when the prediction is a dict.
- Terms compose with `+` and scalar `*` into an `Objective`, e.g. `0.5 * Term(rmse) + Term(fc_corr_loss, key='bold')`.
- `Objective(prediction, target)` returns the weighted sum. `Objective.breakdown(prediction, target)` returns a dict `{name: value}` for logging.
- Both are pytree-free plain callables and safe under jit/vmap/grad.

**`Fitter` (`_fitter.py`).**
- **Two modes.**
  - *Functional:* `Fitter(simulate, objective, space, ...)`. `simulate(params: dict) -> prediction` is pure, and `space` is a dict `{name: (low, high)}` (Quantity bounds allowed) or `{name: None}` for an unbounded value with an initial value from `init`.
  - *Module:* `Fitter.from_module(model, predict, objective, ...)`.
    - It collects `brainstate.nn.Param(fit=True)` parameters, reusing each Param's own transform (`SigmoidT`, `ClipT`, …) for bounds.
    - It functionalises `predict(model)` into `simulate(params)` by writing the unconstrained values into the Params' `ParamState`s inside a `brainstate.transform.StatefulFunction`/`vmap(in_states=...)`, so starts can be vmapped.
    - Best values are written back to the model only after `fit` finishes.
- **Backends.**
  - `'grad'` (default): F2's multi-start minimiser over the unconstrained space, all starts vmapped.
  - `'scipy'`: `braintools.optim.ScipyOptimizer`.
  - `'nevergrad'`: `braintools.optim.NevergradOptimizer`. Candidates are evaluated as one vmapped batch through `simulate`, not a Python loop.
- **Call.** `fit(target, *, n_starts=1, key=None, n_steps=..., transient=None)` returns `FitResult`, a dataclass:
  - `best_params` (constrained, units restored), `best_loss`;
  - `params` and `losses` per start;
  - `history` (per-step losses for `'grad'`, as `(S, n_steps)`);
  - `converged`, `backend`, `raw`.
- **Regularisation.** In module mode, `model.reg_loss()` is added when present, as brainmass does.

**`sweep` (`_sweep.py`).** `sweep(fn, grid, *, mode='product'|'zip', batch_size=None)`:
- Evaluates a pure `fn(params: dict)` over a parameter grid.
- `'product'` takes the cartesian product of 1-D arrays; `'zip'` takes equal-length arrays.
- Runs `jax.lax.map(..., batch_size=)` over vmapped chunks, so memory is bounded by `batch_size`.
- Returns the stacked outputs reshaped to the grid shape, plus the flattened parameter table.
- This replaces brainpy's `running` utilities for parameter exploration.

**Uncertainty (`_uncertainty.py`).** `hessian_ci(loss, best_params, *, confidence=0.95, kind='sse', n_data=None)`:
- Laplace or curvature confidence intervals from the Hessian, taken in the constrained space at the optimum.
  - `kind='nll'`: `cov = H⁻¹`.
  - `kind='sse'`: `cov = 2 s² H⁻¹` with `s² = SSE/(n_data − p)`.
- Returns `(estimate, stderr, low, high)` per parameter.
- Reference: a linear regression, where the CIs equal the OLS CIs from `statsmodels.OLS(...).fit().conf_int()`.

## F4 — `fit.losses`

Module `fit/_losses.py`. Every loss has the signature `loss(prediction, target, **static_options) -> scalar`, is differentiable where meaningful, and its docstring states that.

| Loss | Notes |
|---|---|
| `mse`, `rmse`, `mae` | Over time series (time axis 0). The `transient` trimming is done by `Fitter`. |
| `correlation_loss` | `1 - Pearson r`. |
| `fc_correlation_loss`, `fc_rmse` | On functional-connectivity matrices computed with `analysis.population.functional_connectivity` (upper triangle). |
| `fcd_ks`, `fcd_wasserstein` | Distance between the FCD distributions. Ported from `brainmass.objectives` with identical numerics; tested against brainmass when it is installed. |
| `ks_distance(p, q)`, `wasserstein_1d(p, q, x)` | Ported from brainmass, with identical numerics. |
| `psd_log_distance(pred, target, dt, nperseg, band=None)` | Mean squared log10-PSD difference (Welch through `analysis.spectral`), optionally restricted to a band. |
| `rate_loss(pred, target, dt)` | Squared difference of mean firing rates (Hz) from dense rasters or `SpikeTrains`. |
| `cv_loss(pred, target)` | Squared difference of the mean ISI CV (`analysis.spike.cv`), ignoring NaN neurons. |
| `van_rossum_loss(pred_raster, target_raster, tau, dt)` | Differentiable van Rossum distance on dense rasters: an exponential filter applied by `scan`, then L2. It is differentiable through surrogate-gradient spikes, and equals `analysis.spike.van_rossum_distance` on grid-aligned spikes up to discretisation (this is tested). |

## Verification (exit criteria)

1. The full suite, one process per subpackage, has no new failures.
2. **Parameter recovery.**
   - A Hopf oscillator: fit the frequency and the bifurcation parameter from a simulated trace.
   - A Wilson–Cowan model: fit two coupling weights from simulated rates.

   Both use `Fitter` with `n_starts=8`. The recovered values must be within 5% of the truth, and the tests must take under about 60 s on CPU. brainmass is not imported; the toy models are defined in the test.
3. The NWB, NEO and HDF5 round-trip tests pass in the reference environment.
4. Coverage of the new modules is at least 90%, and mypy is clean on `braintools/fit` (added to `[tool.mypy] files`).
5. The docs build has no warnings in the gated areas; `fit` is added to the gate.

## Edge cases to test

- **`odeint`:**
  - `t1 == t0`, which gives only `y0`;
  - `save_every` not dividing `n`;
  - pytree and Quantity states;
  - `checkpoint=True` giving the same gradient as without.
- **`solve_ivp`:**
  - a stiff-ish problem hitting `max_steps` (`success=False`, no NaN);
  - `t_eval` at the span ends;
  - integrating backwards in time (`t1 < t0`), or rejecting it with a clear error.
- **Multi-start:**
  - every start already at the optimum;
  - a non-finite loss at some starts, which are marked not converged and never selected as best.
- **`Fitter`:**
  - a parameter with Quantity bounds;
  - a module with no `fit=True` params (raise);
  - `n_starts=1` versus vmapped starts giving identical results for the same start;
  - the scipy and nevergrad backends on a 2-parameter problem.
- **`sweep`:** `batch_size` not dividing the grid; `zip` with mismatched lengths (raise).
- **HDF5:**
  - keys containing `/`;
  - 0-d arrays;
  - bool and int dtypes;
  - `SpikeTrains` with `overflow=True`, which is preserved.

## As built: deviations from this plan

These were decided during implementation and review. The code and its docstrings are the reference.

- **`solve_ivp`.**
  - It lands steps exactly on every `t_eval` point instead of interpolating with cubic Hermite polynomials. This gives errors equal to or lower than SciPy's, at the cost of about one extra step per point.
  - It works in two passes. A stop-gradient adaptive pass decides accept/reject and the step sizes; a differentiated replay then repeats the accepted steps. A rejected attempt that produced NaN therefore cannot poison the gradient.
  - The replay uses a checkpointed scan by default (`checkpoint=True`). For N=1e4 states, 4096 `max_steps` and 10 `t_eval` points, gradient memory falls from 1.5 GB to 7 MB.
  - With `t_eval`, accepted states are written directly into a `len(t_eval)` buffer.
- **`odeint`** takes `n_steps=` as an alternative to `t1`, and supports backwards integration with a negative `dt`.
- **`multistart_minimize`.**
  - `MultiStartResult` has an extra `history` field.
  - The gradient convergence test is taken in the bounded parameter space.
  - Starts on a bound are moved 1e-3 of the box width inside it.
  - The relative loss-change test applies only to L-BFGS.
  - Diverged starts are never chosen as best while a finite, non-diverged start exists.
- **`Fitter`.**
  - Its `'scipy'` backend calls `scipy_minimize_with_jax` once per start, in the unconstrained space with starts drawn from `key`, instead of using `ScipyOptimizer`. `ScipyOptimizer` draws its starts from the global NumPy random generator.
  - Its `'nevergrad'` backend seeds nevergrad from `key` and restores the global NumPy random state afterwards.
- **`hessian_ci`** returns a `HessianCI` NamedTuple.
- **`fit.losses`.**
  - `fc_rmse` keeps the spec's upper triangle. It relates to brainmass's full-matrix value by `L_brainmass = L·√((n−1)/n)`.
  - The FCD losses evaluate the KDE in checkpointed blocks. Gradient memory at T=5000 falls from 588 MiB to 36 MiB, with numerics identical to brainmass.
- **`file`.**
  - The NWB writer stores the recording bounds in an `intervals/braintools_recording` table, so zero-neuron trains keep them.
  - `from_neo` takes optional `t_start`/`t_stop` bounds.
