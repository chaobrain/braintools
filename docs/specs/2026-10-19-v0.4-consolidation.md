# v0.4 — Consolidate and place: spec and plan

- **Roadmap:** `docs/specs/2026-10-19-roadmap.md`, phase 0.4 (items C1–C7)
- **Branch:** `phase/0.4-consolidation`
- **PR:** one PR for the whole phase

## Goal

By the end of this phase every existing function is in its final home, and the infrastructure that new code needs is in place:

- one deprecation mechanism;
- the `braintools.analysis` and `braintools.spike` packages;
- truthful packaging, CI and docs.

This phase adds no new analysis algorithms; those come in 0.5.

## Global rules for this phase

- **Deprecate, then remove.** Every moved public name keeps working through an alias that warns **when called**, never when imported or accessed. All aliases use `since='0.4.0'` and `removed_in='1.0.0'`.
- **Behavior is preserved.** Moved functions are moved verbatim except for import paths. Numerical results must be identical.
- **Use new paths internally.** braintools' own code and tests must never call a deprecated alias outside `pytest.warns`. This is enforced through the pytest `filterwarnings` setting (§C1).
- **Tests move with their code**, following AGENTS.md rule 9: `foo.py` ↔ `foo_test.py`. A test file that exercises several modules is split across those modules' test files.
- **Docstrings** use NumPy style with `.. code-block:: python` doctest examples (AGENTS.md).

## C1 — Shared deprecation mechanism

New module: `braintools/_deprecation.py`, which replaces `braintools/input/_deprecation.py`.

```python
class BraintoolsDeprecationWarning(DeprecationWarning): ...

@dataclasses.dataclass(frozen=True)
class DeprecationRecord:
    old_name: str          # fully qualified, e.g. 'braintools.metric.firing_rate'
    new_name: str          # replacement shown to users (dotted path or short phrase)
    since: str             # '0.4.0'
    removed_in: str        # '1.0.0'
    kind: str              # 'function' | 'class' | 'argument' | 'feature'
    alias: object = None   # the alias object, for 'function' / 'class'
    target: object = None  # what the alias forwards to

def register_deprecation(old_name, new_name, *, since, removed_in, kind, alias=None, target=None) -> DeprecationRecord
def warn_deprecated(record, stacklevel=2) -> None
def deprecated_function(new_func, old_name, new_name, *, since='0.4.0', removed_in='1.0.0') -> Callable
def deprecated_class(new_class, old_name, new_name, *, since='0.4.0', removed_in='1.0.0') -> type
def registered_deprecations() -> tuple[DeprecationRecord, ...]
```

**Warning message:**

```
`{old_name}` is deprecated since {since} and will be removed in {removed_in}. Use `{new_name}` instead.
```

**Function aliases.**
- Built with `functools.wraps(new_func)`.
- `__name__` and `__qualname__` are set to the old short name, and `__module__` to the old module.
- `__deprecated__` is set to the warning message (PEP 702 style).

**Class aliases.**
- A subclass of the target whose `__init__` warns and then calls `super().__init__`.
- `__name__`, `__qualname__` and `__module__` follow the old name.

**Registry test** (`braintools/_deprecation_test.py`). For every registered record:
1. For `function` and `class` records, `old_name` resolves through import plus `getattr` to `record.alias`. This proves the alias is actually exported.
2. Calling a function alias, or instantiating a class alias, emits `BraintoolsDeprecationWarning` carrying the message. The test uses the mechanism's own probe functions and does not call arbitrary aliases.
3. `alias.__wrapped__ is target` for functions, and `issubclass(alias, target)` for classes.
4. `removed_in` is strictly greater than `braintools.__version__`, compared as a simple numeric tuple with no new dependency. Once a release reaches `removed_in`, this test fails, which forces the removal.

**pytest configuration.** Add to `pyproject.toml`:

```toml
[tool.pytest.ini_options]
filterwarnings = ['error:`braintools\.[^`]*` is deprecated since:DeprecationWarning']
```

This makes braintools' own tests fail if they call a deprecated alias outside `pytest.warns`. The filter matches the standard message on the builtin category instead of naming `BraintoolsDeprecationWarning`: resolving that class would import braintools while pytest reads its configuration, before pytest-cov starts, and coverage would be under-reported.

**Scaffolding, done in C1 so the parallel agents never edit the same file:**
- Create `braintools/analysis/__init__.py` and `braintools/spike/__init__.py` as empty packages with `__all__ = []`.
- Register both in `braintools/__init__.py`, in its imports and in `__all__`.

**Top-level aliases in `braintools/__init__.py`:**

- The `spike_bitwise*` names stay as **plain, non-warning** aliases of the new functions, because brainstate's `nn/_elementwise.py` uses them. They stay in `__all__`.

**`SpikeTrains`**, in `braintools/spike/_spike_trains.py`. It is a JAX pytree registered with `jax.tree_util.register_pytree_node_class`.

| Field | Shape | Meaning |
|---|---|---|
| `times` | `(N, K)` | Spike times, sorted ascending per neuron. Padding is `+inf`. A Quantity when the time unit is known, otherwise a plain array. |
| `counts` | `(N,)` int32 | Number of valid entries per neuron |
| `t_start`, `t_stop` | scalars | Same unit as `times` |
| `overflow` | scalar bool | Some neuron had more than `K` spikes (only possible when traced, see below) |

- All fields are leaves. `N` and `K` come from the array shapes, so they are static under `jit`.

**Constructors:**
- **`from_dense(spikes, dt=None, t_start=0, capacity=None)`**
  - `spikes` has shape `(T, N)`, time on axis 0. Spike time = `t_start + i*dt`, and `t_stop = t_start + T*dt`.
  - `dt` defaults to `brainstate.environ.get_dt()`.
- **`from_events(times, neuron_ids, n_neurons, t_start=None, t_stop=None, capacity=None)`**
  - Takes flat arrays.
  - `t_start` and `t_stop` default to the minimum and maximum of `times`, which requires concrete arrays.
- **`from_list(trains, t_start=None, t_stop=None)`**
  - Takes ragged per-neuron arrays. Host only.

**Capacity and overflow policy:**
- If `capacity` is None, it is computed from concrete data as `max(1, max count)`. Passing `capacity=None` with traced input raises `ValueError`, and the message explains how to pass `capacity`.
- With concrete inputs, overflow (any count above `capacity`) raises `ValueError`.
- With traced inputs, the first `K` spikes per neuron are kept, `counts` is clipped to `K`, and `overflow=True` is set. The `check()` method raises on overflow in eager mode.
- This contract is documented in the class docstring.

**Methods and properties:**
- `n_neurons`, `capacity`, `mask` (`(N, K)` bool), `duration`
- `to_dense(dt=None)` → `(T, N)` bool, where `T = round((t_stop - t_start) / dt)`
- `to_events()` → flat `(times, ids)` sorted by time. Host only, because the result is ragged.
- `to_list()`
- `bin(bin_size)` → counts with shape `(n_bins, N)`, where `n_bins = ceil(duration / bin_size)` must be concrete
- `window(t0, t1)` → a new `SpikeTrains` restricted to `[t0, t1)`, keeping the same capacity
- `select(idx)` → a subset of neurons
- `check()`
- `__repr__`

All methods except the host-only ones must work under `jit` and `vmap`, and every docstring says which methods are host-only.

**Units:**
- If `dt` or the input `times` are brainunit Quantities, the units are preserved.
- `bin` and `window` accept Quantities in compatible units.
- Plain floats are allowed for unitless use.

**Visualize integration:**
- Move the helpers `flatten_spikes` and `inter_spike_intervals` from `braintools/visualize/_utils.py` into `braintools/spike/_convert.py`. They become private helpers used by `SpikeTrains.from_list` and `to_events`. `visualize/_utils.py` imports them from there, and `as_array` stays in `visualize`.

The orphans are `visualize/_audit_20260619_test.py`, `_audit_fixes_test.py`, `_colormaps_extra_test.py`, `_interactive_extra_test.py`, `_neural_extra_test.py`, `_plots_extra_test.py`, `_statistical_extra_test.py`, `_three_d_extra_test.py` and `_visualize_test.py`.

## Verification (exit criteria)

1. **Full test suite.** There must be no new failures compared with the pre-phase baseline. On `origin/main` @ `2e0c016` with saiunit 0.5.2, the baseline is 4,294 passed and 40 skipped, all green; with saiunit 0.5.1 there is 1 failure, in `tree_test`.

   A single full-suite pytest process peaks at **13.3 GB RSS**. To stay safe on WSL, run the suite as one process per top-level subpackage, one after another, never all in one process.

   *Found during integration:* almost all of that peak came from a single `file` test that allocated an 11 GB byte string to check a size limit. It now uses an 11-byte payload, and every subpackage process stays under about 2 GB.
2. **Deprecation filter.** The pytest `filterwarnings` setting turns any `BraintoolsDeprecationWarning` raised outside `pytest.warns` into an error, and the suite still passes.
3. **Downstream smoke tests.** Locally installed brainpy, brainmass and brainpy_state still import, and their uses of braintools still work. Run a targeted script that exercises the downstream call sites, and expect warnings rather than errors.
4. **Docs.** The Sphinx build has no new warnings that mention `analysis`, `spike` or moved names.
5. **Coverage.** Coverage of new or changed modules (`_deprecation`, `spike`, `analysis`) is at least 90%.

## Edge cases to test

- **Deprecated aliases:** pickling a deprecated function alias; `isinstance` checks against a deprecated class alias's target; calling an alias inside `jax.jit` (it should warn once at trace time).
- **`SpikeTrains.from_dense`:**
  - all-zero spikes, with `capacity` defaulting to 1;
  - a single time step;
  - `capacity` smaller than the maximum count, both eager (must raise) and traced (must set the flag);
  - Quantity `dt` against float `dt`.
- **Round-trips:** dense → events → dense; `from_list` with empty trains.
- **`bin`:** a bin size that does not divide the duration evenly (the last bin is partial).
- **`window`:** spikes exactly at the boundaries `t0` and `t1`.
- **`vmap`** of `from_dense` over trials with a fixed `capacity`.
- **`MorphologyDistance`** with every legacy decay string.
- **Removal-version check:** the registry test fails if `__version__` is at least `removed_in`.
